# 决策：全局扁平备份目录

状态：已实施
类别：architecture

## 背景

Claude Code 把文件备份存 `~/.claude/file-history/{sessionId}/{hash}@vN`，按会话分目录，fork/resume 时用硬链接迁移（`copyFileHistoryForResume`）。本扩展最初设计为**全局扁平** `~/.pi/agent/pi-rewind/backups/{hash}@vN`。

## 决策

备份名不含会话维度，全局共享——fork 后旧分支快照引用同一备份文件，天然可用，无需复制迁移。作为代价，**版本号必须扫磁盘现存文件的最大 v+1**（`maxExistingVersion`），否则新会话/新实例对同一路径重算 v1 覆盖旧备份。

## 已考虑替代方案

- **按 sessionId 分目录（CC 方案）**：目录隔离消除版本冲突，但 fork/resume 需显式迁移备份（复制或硬链接），且多一层关联逻辑。落选：pi 会话 fork 是树内分支（同文件路径），共享备份更简单；迁移逻辑是纯负债。
- **扁平 + 备份名带 sessionId 前缀**：`{hash}@s{sid8}@vN`。落选：备份名变长、恢复时需解析嵌套版本段，且分叉后仍要决定继承哪个会话前缀——复杂度不超过收益。

## 后果

- 单一共享名空间 → `maxExistingVersion` 扫磁盘是硬约束（违反会静默覆盖旧备份，见 [EXPERIENCE#6](../EXPERIENCE.md#6-全局扁平备份目录--版本号必须扫磁盘)）。
- fork/多实例复用同一物理复用同一备份文件，磁盘占用天然去重（相同内容同名文件不重复写）。
- `.git` 无关、跨项目隔离靠 hash 内含的绝对路径（不同项目路径 hash 不同）。
