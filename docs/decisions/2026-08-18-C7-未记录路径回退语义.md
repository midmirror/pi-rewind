# 决策：C7 未记录路径的 v1 三分支回退

状态：已实施
类别：architecture

## 背景

`applySnapshot(meta)` 恢复「至某用户消息之前」。目标快照 `meta.files` 未必包含所有被跟踪路径——某些文件在**更晚**才首次被编辑。CC 的 `getBackupFileNameFirstVersion` 提供回退规则。

## 决策

对目标快照「未记录」的路径，查该路径全历史首个记录（v1），三分支：
- `findFirstVersion` 返回 undefined（从未被任何快照跟踪）→ **跳过**（不触碰磁盘——该文件从未由 agent 改过，恢复无意义且可能是用户/外部文件）
- v1.backup === null（首次记录时文件不存在）→ **删除** 磁盘文件（目标时刻该文件确实不存在）
- v1.backup 有文件名 → **恢复到 v1 备份内容**（目标时刻之前该文件已被创建）

## 已考虑替代方案

- **未记录一律删除**（`{backup:null}` shorthand）：实现者对场景 B/C 的过度简化。在「文件历史 v1 有真实内容」时误删已存在文件——数据丢失。被二轮审查否决后恢复三分支。
- **未记录一律跳过**：在「目标时刻该文件尚未创建、后又被创建」场景文件残留（违反恢复语义）。落选。

## 后果

- 恢复正常，且对「目标时刻该文件存在/不存在」两种历史都能给正确结果。
- 前提：`trackEdit` 从 v1 起、`makeSnapshot` 单调递增版本，故「全历史首个记录」恒为 v1（[EXPERIENCE#1](../EXPERIENCE.md#1-null-快照卡死导致恢复误删文件) 的 null 卡死 bug 曾使此假设失效——已修）。
