# 决策：版本号分配统一扫描磁盘（makeSnapshot 变化分支）

日期：2026-08-19

## 背景

全局扁平备份目录（`~/.pi/agent/pi-rewind/backups/{hash16}@vN`，跨会话共享，见 `2026-08-18-全局扁平备份目录.md`）下，版本号唯一性是设计底座。v0.1.0 里：

- `trackEdit`：`maxExistingVersion + 1`（扫磁盘）✅
- `makeSnapshot` null 分支：`maxExistingVersion + 1`（扫磁盘）✅
- `makeSnapshot` changed 分支：`desc @vN + 1`（按快照内存记录）❌

Changed 分支不扫盘导致跨会话版本落后时覆盖他人备份：会话 B 引用 v1、磁盘已到 v3，B 内容一变按 `1+1=2` 写 v2，恰好覆盖 A 的 v2 备份，A 恢复静默损坏。

## 决策

**同一文件的所有「写新版本」路径，版本号一律 = `max(desc 当前版本 + 1, maxExistingVersion + 1)`，不区分 trackEdit / makeSnapshot 各分支。**

这样既保证单会话内单调递增（`> desc`），又保证跨会话防覆盖（`> 磁盘现存最大`）。`desc 版本 + 1` 是下限，磁盘扫描是上限，取两者 max。

## 备选与取舍

- **内存 per-key 版本号 + hydrate 时扫盘一次**：减少热路径 readdir 次数（每编辑一次）。待测试与基准证明 readdir 是瓶颈后再引入；当前备份数规模下扫盘成本可接受，正确性优先。
- **CC 按 sessionId 分子目录**：彻底规避共享竞争，但破坏全局扁平设计（跨会话天然共享是收益，一个 fork 引用另一会话的备份），当前不采纳。

## 影响

- 每写一个新版本多一次 `readdir` 备份目录，换取跨会话版本唯一性。
- 新增回归测试「回归#1」锁死：「desc 落后磁盘」场景下 changed 分支避让到磁盘最大 v+1，不覆盖他人备份。

## 反方（被否）

「只修 trackEdit 已够」——错误。审查证明同文件三处版本分配法两处一致一处分裂，属共同不变量；逐条核对才会覆盖所有写版本路径。
